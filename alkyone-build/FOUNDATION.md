# Alkyone foundation

Everything a scene author needs. The foundation owns the page shell (nav, rail, footer, tooltip, live regions), the tokens, the component classes, the seams between scenes, the reveal system, the scene scheduler and the glossary. A scene owns only its own `section.html`, `section.css`, `section.js` in `src/sections/<id>/`.

Build: `node build.mjs` (all scenes, writes `dist/index.html`). Options: `--only hero,ring` (build just those; the rest stay placeholders), `--out path`, `--inject file.html` (adds a dev block; `file.css` and `file.js` beside it are picked up), `--src dir` (build another tree, used by the validator tests), `--quiet`. Errors exit 1 and write nothing. The build also rejects includes outside `src/`, `<base>`, `<meta http-equiv>`, style attributes or `image-set()` pointing at files, and `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`, `importScripts`, `new Worker` and `import()` in section or shared JS. Warnings never block.

Kitchen sink (dev only, never shipped): `node build.mjs --inject src/dev/kitchen.html --out dev/kitchen.html`, then open `dev/kitchen.html`.

## 1. Scene skeleton

`src/sections/<id>/section.html` has exactly ONE root. The root must be a direct child of `main` and carry `id`, `class="sec"` and `data-theme`.

```html
<section id="ring" class="sec" data-theme="mist" aria-labelledby="ring-title">
  <div class="container sec__grid">
    <div class="sec__head">
      <p class="eyebrow" data-reveal><span class="eyebrow__num">2</span> <span class="eyebrow__text">The ring</span></p>
      <h2 class="h2" id="ring-title" data-reveal="lines">A quiet ring that taps back.</h2>
      <p class="lede" data-reveal data-reveal-delay="1">...</p>
    </div>
    <figure class="plate sec__visual" data-reveal>
      <div class="plate__badges"><span class="sim-tag"></span></div>
      <div class="plate__stage"><!-- svg or canvas --></div>
      <figcaption class="plate__caption"><span class="plate__fig">Fig. 2</span> Illustration, not to scale.</figcaption>
    </figure>
  </div>
</section>
```

Theme rhythm: hero mist, patch night, ring mist, app mist-teal, sleep night, future mist, team mist-teal. The build writes `data-prev` / `data-next` on the root when a neighbour has a different theme, and each scene paints half of the seam (section 7). Put a real space between `eyebrow__num` and `eyebrow__text` in the markup.

CSS rules (linted): every selector starts with `#<id>` or `.<id>-`; keyframes are named `<id>-...`; `!important` only inside `prefers-reduced-motion`; no `@import`, no external `url()`. JS: one IIFE calling `Alkyone.section('<id>', {...})`. No `console`. Section CSS is unlayered and the foundation is layered, so section rules always win without specificity games.

Semantic theme variables, redefined per `[data-theme="mist|mist-teal|night"]`: `--bg --bg-2 --fg --fg-muted --line --line-strong --surface --surface-2 --accent --accent-hover --accent-ink --warm --warm-ink --focus --hatch --dot --plate-bg --plate-line --plate-shadow --tip-bg --theme-bg-*`. Use these, not the raw palette, for text and borders, so a scene works in any theme.

Use `--warm` (apricot) for display-size text and graphics only. Small text takes `--warm-ink`. Apricot is the page's single accent: one point of focus per scene (the alert, the live dot).

## 4. JS API (`window.Alkyone`)

| Member | Notes |
|---|---|
| `section(id, def)` | `def = { init(ctx), enter(ctx), leave(ctx), progress(p, ctx), resize(ctx), reducedChange(reduced, ctx) }`. `init` runs once when the scene is within one viewport of the screen and may return a promise (enter waits for it). A throw or rejection marks the scene dead and nothing else is affected. Every callback is isolated by try/catch. `progress` p runs 0 to 1 across the scene's pass through the viewport, on a shared rAF, only while the scene is on screen. When a scene leaves or is parked off screen it gets its exact end value (0 below the viewport, 1 above): one last `progress(0|1)` call if it was entered, `ctx.p` and `--p` (with `data-p`) set. |
| `ctx` | `{ id, el, p, pass, reduced, lowPower }` (the last two are live getters). |
| `raf(fn, {fps})` | `fn(t, dt)`; returns an unsubscribe. Sleeps when nothing subscribes and while the tab is hidden. |
| `onResize(fn)` | Debounced; returns an unsubscribe. Section `resize` and `onResize` callbacks are skipped on touch devices when only the height changed by 160px or less (address bar showing or hiding). |
| `reduced` | Live `prefers-reduced-motion` (also `html[data-motion]`). Subscribe with `reducedChange`. |
| `lowPower` | Heuristic (few cores, little memory, save-data). Also `html[data-power="low"]`: the nav blur is dropped. Use it to lower DPR, particle counts, effects. |
| `announce(msg, {assertive})` | Screen-reader live region. The latest message wins; repeats are announced again. |
| `defineTerm(key, html)` | Add or override a glossary entry. HTML is sanitized (`SUB SUP EM STRONG I B BR` only). |
| `reveal(el)` | Register an element added after load. |
| `loadThree()` | `Promise<THREE or null>`, memoized, three r160 from cdnjs then jsDelivr, 10 s budget, never rejects. `null` means: draw the SVG/CSS fallback. |
| `hasWebGL()` | Cached boolean. |
| `vibrate(pattern)` | Safe boolean wrapper (needs a prior user gesture). |
| `util` | `clamp lerp mix smoothstep easeOutQuint easeInOutCubic easeOutBack rng(seed) damp(cur,target,lambda,dtMs) remap dpr(max)`. |

`--p`: the scheduler writes `--p` (0 to 1) on a scene ONLY if its root has `data-p`. The build adds `data-p` automatically when the scene's CSS or JS mentions `--p`. Reason: `--p` inherits, so writing it restyles the whole subtree every frame (measured: style recalc 8.1 s down to 2.4 s over a scripted scroll at 4x CPU throttle). Prefer `progress(p)` to move a few elements directly with `transform` / `opacity`.

Nav and rail follow the theme under the nav (probe line y = 28). The rail is hidden under 1100px wide and the scheduler does not write its progress there.

## 5. Glossary

```html
The patch talks to the ring over <button class="term" data-term="ble">BLE</button>.
```

The 14 contract keys are registered: `ble imu spo2 optical heartbeat ece fusion ml baseline flex ondevice escalation maintenance staging`. Hover opens after 170 ms (instantly if another closed a moment ago); Tab focus opens; click, tap or Enter pins it (and announces politely); Escape, outside tap, scroll, resize or blur closes. A bubble pinned by mouse or touch survives a tap inside it; a bubble opened by keyboard focus closes when focus leaves. The pointer can travel from the term into the bubble without closing it (WCAG 1.4.13). `aria-describedby` exists only while open. The bubble flips and clamps inside the viewport and inverts on night grounds. Use `<button>`, not a link, and write the term as it reads in the sentence. To add one: `Alkyone.defineTerm('key', 'text')` in your `section.js`, then `data-term="key"` in the HTML. Coarse-pointer devices get a larger invisible hit area.

## 6. Reveal

`data-reveal` fades and rises 16px once, on entry. `data-reveal="fade"` fades only, `data-reveal="lines"` splits a headline into words that cascade, `data-reveal-delay="1..6"` staggers in 75ms steps. The hidden state exists only under JS and `prefers-reduced-motion: no-preference`; without JS, with reduced motion, or if the runtime has not reported ready within 4 s (watchdog), everything is simply visible. `is-in` then `is-done` (the component's own transitions are restored after). Do not put `data-reveal` on an element whose own `transform` you animate every frame; wrap it.

## 7. Seams, themes, nav, rail, footer

Each scene paints the half of the transition that touches its own edge: `--seam-half` (clamp 72-110px) with eased stops in oklab; night-to-light seams pass through a blue-500 tint at 36%. Two neighbours together give at least 144px. Do not add your own full-bleed gradient at a scene edge.

The nav bar is .88 opaque on light grounds and .82 on night (checked by pixel sampling over the darkest and lightest content: pill text stays at 4.5:1 or better). The nav is a fixed glass bar with the brand, a progress line and the pill "Concept stage - not a medical device" (only "Concept stage" visible under 480px, full text kept for screen readers). The footer carries the same notice as its headline plus the plain disclaimer. Both are foundation-owned.

## 8. Reduced motion, low power

- Under reduced motion all CSS animation and transition durations collapse to 1ms with one iteration, except elements marked `data-motion-ok`. Smooth scrolling is only enabled for no-preference.
- Your JS must still show a meaningful static state: check `ctx.reduced`, draw one frame, start no loops. Handle `reducedChange` for a live toggle.
- `ctx.lowPower`: cut DPR (`Alkyone.util.dpr()` already does), geometry detail and effects.
- Per-frame SVG: an SVG covering a whole plate that is rewritten every frame was the most expensive thing measured here in software rendering (roughly 20 to 35 fps versus 55 to 60 without it, noisy). Prefer canvas/WebGL, or CSS `transform`/`opacity` on few elements; give a per-frame SVG its own layer with `.layer`; skip attribute writes that did not change; keep the area small.

## 9. Pitfalls and decisions

- Foundation is `@layer reset, tokens, themes, base, layout, components, chrome, utilities, motion`; section CSS is unlayered and wins.
- Buttons, chips and tags are inline-block, not flex: height comes from padding so inline `<sub>` and icons stay with their text.
- Scene visibility uses IntersectionObserver; an element touching the edge exactly is not "intersecting". Tests scroll 40px past the edge.
- `scroll-padding-top` keeps keyboard focus clear of the fixed nav; links to a scene still land flush (negative `scroll-margin-top` on `.sec`).
- Glyphs missing from the fonts' latin subset: command symbol, approx, less-or-equal, greater-or-equal, element-of (and plus-minus in Instrument Serif). Write words, or draw them in SVG. Instrument Serif has no tabular figures: set numbers in Figtree with `.tnum`.
- Fonts are inline woff2 data (about 84 KB of CSS) with metric-matched fallback faces, so there is no layout shift on swap (CLS 0 measured). No external stylesheet is allowed anywhere; the build rejects non-whitelisted URLs.
- No `console` output from the runtime. No browser storage used.
- Honesty rules live in CONTRACT.md: every data-like visual carries a `.sim-tag`; no numbers, claims or certifications beyond the brief.
